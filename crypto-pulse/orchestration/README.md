# Orchestration Layer Mounting Directory

This directory acts as the staging area and placeholder volume mount for system orchestration configurations in **Crypto-Pulse**.

---

## Directory Structure

```
orchestration/
└── .gitkeep        # Keeps the directory structure tracked in git
```

---

## Purpose & Future Extensions

Currently, the orchestration in the project is driven by **Apache Airflow** (which utilizes the `dags/` folder for workflow definitions and `airflow/` for Docker image creation). 

This `orchestration/` directory is designed to serve as:
1.  **Shared Volume Mounts**: Mounting target for runtime logs, metadata database backups, or execution logs generated by the containerized services.
2.  **Plugin Repository**: Storage for custom Airflow operators, hooks, or providers that can be dynamically linked into the system.
3.  **Future Extensions**: Reserved for alternative scheduler components (such as **Prefect**, **Dagster**, or **Kubernetes CronJobs**) if the system is migrated away from Airflow in production.
